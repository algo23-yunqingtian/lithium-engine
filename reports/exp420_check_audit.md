# exp420_check：校验报告 — 核查exp420异常绩效问题

> 生成时间：2026-09-10
> 基准：锁定exp419 T1版本全部参数、阈值、风控，不做任何改动
> 校验目标：定位exp420版本A最大回撤=0%、年化+167.9%的异常根因

---

## 一句话结论

**exp420存在一个严重BUG：position数组不含exit日，导致收益重复计入，最大回撤=0%、年化虚高至+167.9%。** 修正后版本A年化降至+93.9%（非+167.9%），最大回撤从0%恢复至-14.68%。成交假设偏差的结论仍然成立：版本B（T+1开盘成交）年化仍为-19.5%，衰减幅度从186pp缩小至113pp。

## 模块2：净值&回撤计算审计

### 2.1 BUG根因定位

**BUG位置**：`compute_equity_curve_A()` 中 position 数组重建逻辑

```python
# BUG版本（原exp420代码）：
for t in range(ei, xi):  # 不含exit日 ❌
    positions[t] = size

# 修正版本：
for t in range(ei, xi + 1):  # 含exit日 ✓
    positions[t] = size
```

### 2.2 BUG机制详解

exp409.run_ham_dynamic 的时序逻辑：
1. **T日收盘检查平仓条件** → 触发平仓 → 平仓价用 `close[xi]`（exit日收盘价）
2. **trade的exit_date = xi** → 表示exit日平仓

但 `compute_equity_curve_A` 重建position数组时：
- `range(ei, xi)` 不含 `xi` → **position[xi] = 0**
- exit日无持仓 → exit日的价格变动收益 **被重复计入两次**：
  1. 一次在 exit 日的 `close[xi] - close[xi-1]`（由前一笔交易在 xi-1 日的持仓产生）
  2. 一次在下一笔交易的 entry 日（如果紧邻）

这导致：
- **总收益虚高**：重复计入的收益累乘后放大
- **最大回撤=0%**：虚高的净值曲线从未回撤（因为重复计入的收益填补了回撤）
- **年化虚高**：从正确的+93.9%膨胀至+167.9%

### 2.4 逐笔交易公式验证

逐笔交易盈亏公式正确，与exp419完全一致：
- `pos_ret = entry_dir × (exit_price - entry_price) / entry_price`
- `net_ret = pos_ret - 2 × COST_PER_SIDE`
- 51笔交易逐笔对比：`max_diff = 4.7e-7`（浮点精度级别），**完全一致**

### 4.2 修正后结论（保留正确的成交假设偏差）

**成交假设偏差仍然存在，但幅度比原exp420报告的更小：**

1. **版本A年化从+167.9%修正为+93.9%** — 原报告高估了74pp
2. **衰减幅度从186pp修正为113pp** — 仍然显著
3. **版本B年化仍为负（-19.5%）** — 方向正确，T+1开盘成交导致策略亏损
4. **版本A最大回撤从0%修正为-14.68%** — 原报告完全掩盖了回撤

**核心结论不变**：HAM策略的"日内T+1"特性对成交时点极度敏感。T+1开盘成交导致年化从+93.9%暴跌至-19.5%，策略本质是赌隔夜跳空方向，开盘价执行时该赌注失效。
