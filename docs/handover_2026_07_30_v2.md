## 四、系统需要完善的地方

### 1. cron 定时任务缺失
- `agent_daily_update.py` 目前需要手动运行，未加入 cron
- 建议创建 cron job 每天 18:30 自动运行，持续积累数据
- **关键**: 回推脚本 `backfill_agent_history.py` 和扩充脚本 `expand_spreads.py` **不要加入 cron**，只跑一次

### 2. 库存数据依赖 cron 增量导入
- `inventory_history` 表通过 cron 从 Excel 增量导入
- 如果库存 cron 断了，agent 评分中库存相关逻辑会降级（用最近数据）

### 3. spreads 表扩充脚本不要重复执行
- `expand_spreads.py` 中有 `DELETE FROM spreads`，重复执行会清空已有数据
- 只执行一次，之后靠每天 cron 增量导入 spreads

### 4. 数据一致性
- 确保 daily update 脚本和 backfill 脚本的评分逻辑一致
- 如果修改了 `compute_agent_score` 的评分规则，需要用 `backfill_agent_history.py` 重新回推

### 5. notes（小作文）数据缺失
- `notes` 表最新只有6月5日数据，7月无数据
- 导致7月所有回推数据中情绪因子归零
- 如果未来接入 SMM 新闻等情绪源，需要用 backfill 脚本重新回推

### 6. 前端展示
- 甘特图横轴日期较密，22天 × 7个agent 的散点可能拥挤
- 如果后续天数继续增加，可能需要调整渲染密度

### 数据库
- **Flask 使用**: `lithium.db`（`/home/ubuntu/lithium_calendar/lithium.db`）
- **备用**: `lithium_v2_20260730.db`（不要混淆！）

### API 端点
| 端点 | 说明 |
|------|------|
| `/api/battlefield` | 仪表盘主数据（agents + history + decisions） |
| `/api/logic-scores?days=30` | 7维逻辑强度 |
| `/api/agent-interactions?days=30` | 互动关系 |
| `/api/battlefield/history?days=30` | 历史观点序列（甘特图） |
| `/api/term-structure` | 期限结构+月差 |

### 代码修改要点
1. **`lithium_api.py`**: `agent_history` 查询 LIMIT 已从 100 改为 500（2026-07-30 修改）
2. **`agent_daily_update.py`**: `compute_agent_score()` 返回 `logic_scores` dict + 7维评分
3. **`game_factors.py`**: `apply_game_factors()` 中新增互动关系记录
4. **`battlefield_agents.html`**: 前端固定 fetch 30天数据（`days=30`），如果需更多天数，改前端 JS

### 回退
- 如果前端报错：检查浏览器控制台，ECharts 初始化失败通常是 DOM 元素不存在
